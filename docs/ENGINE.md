# Phase 2 엔진 규칙

## 실행 흐름

`generateBirth()` → `startLife()` → `advanceLife()` × 12 → 엔딩.

브라우저에서는 `GameSession`을 통해 출생 확정과 선택을 실행한다. 상태는 복사본으로만 반환한다. 새 인생 확정·선택 완료·단계 변경·엔딩은 상태 전이가 끝난 뒤 자동 저장된다. 저장 실패는 현재 인생을 중단하지 않고 안내를 표시한다.

| 모듈 | 역할 |
|---|---|
| `conditions.ts` | 기존 출생 조건과 완료 사건·선택 이력을 재귀적으로 판정 |
| `effects.ts` | 효과 순서 실행, 0~100 제한, 변신, 실패 시 원본 상태 보존 |
| `events.ts` | 단계, 대상 필터, 선택 가능 여부, 방문 제한, 혼돈 가중치, 안전 추첨 |
| `branching.ts` | 직접·조건·일반·안전 순서와 선택된 경로 보고 |
| `endings.ts` | 복합 조건과 우선순위·ID에 따른 일관된 엔딩 선택 |
| `game.ts` | 인생 시작, 선택 기록, 12회 진행, 운명 공개, 엔딩 전환 |
| `save.ts` | 저장 형식·버전·재현 검사, localStorage 실패 처리 |
| `session.ts` | 상태 보관, 재추첨 제한, 자동 저장, 오래된 선택 입력 차단 |

## 단계와 이력

출생 생성 화면은 `birth`다. 인생 확정 후 완료 횟수 0~1은 각성, 2~3은 성장, 4~5는 위기, 6~7은 전환, 8~11은 절정, 12는 결말이다. 생존력 0은 마지막 엔딩 조건에 반영하며 조기 종료를 만들지 않는다.

`visitedEventIds`에는 진입한 현재 사건도 포함된다. `event`·`choice` 조건은 선택을 마친 `choiceHistory`만 조회한다. 현재 사건 자체를 과거 사건으로 오인하지 않는다. 효과 실행 후 선택 기록을 추가하고, 다음 단계에서 분기를 평가한다.

일반 사건은 같은 인생에서 한 번만 진입한다. 반복·자기 참조 목적지는 방문 제한으로 제외한다. 다음 후보가 없으면 JSON의 안전 사건을 사용한다. 안전 사건만 12회까지 반복할 수 있고, 선택 총합 12회에서 반드시 엔딩으로 넘어간다.

`GameSession.choose()`는 사건 ID와 화면을 만들 당시 완료 횟수를 함께 받는다. 연속 클릭이나 안전 사건 반복 중 오래된 버튼 입력도 추가 선택으로 처리하지 않는다. `GameSession.roll()`은 출생 미확정 또는 엔딩 상태에서만 허용한다.

## 변신과 운명

변신은 현재 세계관 안에서만 지원한다. 현재 존재 ID와 새 존재의 태그를 반영하되 능력치·기존 태그·아이템·플래그·이력·출생 ID·운명을 보존한다. 초기 능력치를 다시 적용하지 않는다. 선택 기록의 존재 ID는 그 선택을 했을 당시 모습이다.

숨겨진 운명은 출생 존재의 데이터를 기준으로 읽는다. `revealsFate` 사건 진입 전에는 UI에 이름·설명을 제공하지 않는다. 샘플의 운명 사건은 출생 때 받은 운명 플래그를 조건으로 사용한다. 변신 후에도 같은 운명과 공개 상태를 유지한다.

## 저장과 복구

- 키: `life-game.save.v1`.
- 형식: `{ saveVersion: 1, state: GameState }`.
- 출생 미확정 상태는 저장하지 않는다. 시작 후 첫 사건을 배정한 상태부터 저장한다.
- 스키마·콘텐츠 버전 확인 후 시드에서 출생을 재생성하고 선택 이력을 재실행한다. 복원된 전체 상태가 저장값과 같아야 이어간다.
- 이 검사는 우발적 손상·잘못된 참조·상태 불일치 검출용이며 보안용 서명이나 온라인 부정행위 방지 기능은 아니다.
- 저장 문자열은 최대 250,000자로 제한한다. 최대 12개 선택을 재현하므로 복구 작업도 제한된다.
- 호환되지 않거나 손상된 저장은 자동 삭제하지 않는다. 새 인생을 확정해 정상 저장할 때 교체한다.
- localStorage getter·읽기·쓰기 예외는 사용자 안내로 처리한다. 저장 실패 시 진행 중 메모리 상태와 마지막 정상 저장을 유지한다.
- 개인정보나 외부 서버는 사용하지 않는다. 실제 제3자 iframe에서 저장이 제한되는 환경은 Phase 5에서 확인한다.

## 자동 검사와 한계

`simulateContent()`는 기본적으로 시드 0~63과 첫 선택·마지막 선택·순환 선택·별도 난수 선택의 네 전략으로 256회 완주하며 Phase 2 회귀에 이 표본을 유지한다. MVP의 `simulateMvpContent()`는 각 세계를 고르게 검사하도록 해당 세계의 원본 출생·사건·엔딩을 사용하고 시드 0~4095 × 네 전략, 6세계 총 98,304회로 확장한다. 게임 난수와 전략 난수는 분리한다. 모든 등록 출생 유형, 일반 사건, 선택지, 직접·조건 분기, 엔딩의 관측 여부를 확인한다. 미도달이나 정상 경로에서의 안전 사건 사용이 있으면 콘텐츠 검증 명령이 실패한다.

유한 시뮬레이션은 임의의 JSON 조건 전체를 증명하지 않는다. 미도달은 우선 조건·우선순위·단계·선택 전략을 점검할 신호다. 콘텐츠 확장 시 재현 가능한 시드나 목적에 맞는 테스트를 추가하고, 검사를 삭제하거나 조건을 완화하지 않는다. 안전 사건 고갈 대응은 별도 테스트로 확인한다.

기존 Phase 1·2 회귀 테스트는 `tests/fixtures/phase1/`, `phase2/`의 당시 데이터로 유지한다. `gameplayContent()`는 Phase 2 기준, `mvpContent()`는 배포할 최신 JSON을 읽는다. MVP 통합 테스트는 세계 격리 없이 전체 원본 추첨으로 30개 출생 유형을 찾아 각각 12개 사건을 진행하고 모든 저장 시점에서 복원 결과와 다음 선택 결과를 비교한다. 다섯 변신 경로의 출생·이력 유지와 실제 이전 콘텐츠 저장의 비호환 안내도 검사한다.
