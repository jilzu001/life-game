# 콘텐츠 규격 v1

## 원본과 검증

`src/content/schema.ts`가 콘텐츠 규격의 원본이다. TypeScript 타입은 이 정의에서 추론하며, `npm run schema:generate`는 `schemas/`에 manifest·world·entity·event·ending·game-state JSON Schema를 생성한다. 생성된 파일을 직접 편집하지 않는다. 검증기는 JSON Schema와 원본의 동기화도 검사한다.

모든 객체는 엄격한 검증을 사용한다. 알 수 없는 필드, 누락된 필수 필드, 문자열로 작성한 숫자, 잘못된 연산자, 지원하지 않는 버전은 거부한다. 현재 `schemaVersion`은 1, `contentVersion`은 `0.4.0-mvp`다. 저장 콘텐츠 버전이 현재와 다르면 새 인생 시작을 안내한다. Phase 1·2 데이터도 같은 스키마로 읽을 수 있다.

## 파일 등록과 경로

- `public/content/manifest.json`의 `worlds`, `entities`, `events`, `endings`에 파일 상대 경로를 등록한다.
- 파일 하나에 문서 하나를 작성한다. 파일 검색이나 파일명 추측은 하지 않는다.
- ID는 `[a-z][a-z0-9_]*` 형식이다. 세계관·존재·사건·엔딩 ID는 전체에서 고유하며, 출생 옵션 ID는 존재의 해당 그룹 내에서 고유하다.
- 모든 이미지 경로는 `public/content/` 기준 `images/...svg` 또는 `images/...webp`다. URL, 루트 절대 경로, `..`, 쿼리 문자열, 역슬래시는 허용하지 않는다.
- 브라우저는 Vite `BASE_URL` 아래의 `content/`를 기준으로 JSON과 이미지를 해석한다.
- SVG에는 `viewBox`가 필요하다. 현재 단순 벡터 자산 검증은 스크립트, 이벤트 속성, 외부 참조, style·image·use·foreignObject·애니메이션 요소를 거부한다. 지원 범위를 확장해야 하면 별도 검토한다.

## 출생 순서와 가중치

세계관 → 존재 → 위치 → 특징 → 결함 → 숨겨진 운명 순서다. 세계관과 존재에도 양수 `weight`를 지정한다. 존재에는 `timeUnit`, `birthStory`, 초기 능력치, 태그, 출생 옵션 목록을 둔다.

각 출생 옵션은 `id`, `name`, `description`, `weight`, `flags`, `effects`가 필수이며 `conditions`는 선택이다. 위치·특징·결함은 각각 최소 2개, 숨겨진 운명은 최소 1개다. 그룹별 최대 32개이며 가중치는 0보다 크고 1,000,000 이하다.

옵션 조건은 **선택 전** 상태에서 판정하고, 선택 후 플래그와 효과를 목록 순서대로 적용한다. 위치·특징·결함 조건에서 아직 추첨하지 않은 필드를 참조할 수 없다. 출생 옵션에서 사건 이력을 참조하거나 존재를 변신시키는 것은 허용하지 않는다.

완성 가능한 조합을 먼저 열거하고 각 단계의 유효 후보를 가중 추첨한다. 후속 옵션이 많은 조합이 앞 단계의 추첨 확률을 부풀리지 않는다. 탐색은 100,000개 노드에서 제한되며, 초과·유효 조합 없음·도달 불가능 옵션은 오류로 보고한다. 추첨에 실패한 뒤 무한히 다시 뽑는 방식은 사용하지 않는다.

샘플에서는 마력 흡수 특징이 저주도 흡수하므로 저주받은 칼날과 함께 나오지 않는다. 왕실·유적 출생은 다른 능력치·플래그·숨겨진 운명으로 연결된다.

## 조건과 효과

조건은 비어 있지 않은 `all` 또는 `any`로 중첩할 수 있다. 무조건인 경우 `conditions`를 생략한다.

| 조건 종류 | 필드 |
|---|---|
| `stat` | `key`, `operator: gte/lte/equals/notEquals`, 숫자 `value` |
| `flag`, `tag`, `item` | `key`, `operator: equals/notEquals`, 불리언 `value` |
| `world`, `entity`, `location`, `trait`, `flaw` | `operator: equals/notEquals`, ID `value` |
| `event` | `eventId`, `operator: equals/notEquals`, 불리언 `value` |
| `choice` | `eventId`, `choiceId`, `operator: equals/notEquals`, 불리언 `value` |

능력치는 `survival`, `influence`, `intelligence`, `freedom`, `chaos`의 다섯 개다. 초기·설정 값은 0~100이며 더하기 효과의 결과도 0~100으로 제한한다. 없는 플래그·태그·아이템은 미보유로 판정한다.

| 효과 | 필드 |
|---|---|
| `addStat`, `setStat` | `key`, 숫자 `value` |
| `setFlag` | `key`, 불리언 `value` |
| `addTag`, `removeTag`, `addItem`, `removeItem` | `key` |
| `transformEntity` | `entityId` |

`addStat` 값은 -100~100, `setStat` 값은 0~100이다. `transformEntity`는 사건 효과에서 실행하며 현재 세계관 안에서만 변신한다. 출생 정보·능력치·플래그·아이템·기록을 보존하고 새 존재의 태그를 기존 태그에 합친다. 기존 태그를 없애려면 `removeTag`를 명시한다. 조건과 효과는 Phase 2 사건 실행기에 연결되어 있다.

## 사건과 엔딩

사건은 `worldIds`, `entityIds`, `entityTags`, `stage`, `title`, `description`, `image`, `weight`, `choices`, `branches`가 필수다. 공통 사건의 대상 배열은 빈 배열로 둘 수 있다. 존재 ID와 태그가 모두 지정되면 둘 중 하나가 일치하면 되고, 세계관·단계·발생 조건은 모두 충족해야 한다. `stage`는 생애 단계 ID 또는 `any`다. 선택지는 2~3개이며 `resultText`, `effects`, `branches`를 가진다. 조건부 선택지는 조건을 만족할 때만 제공한다.

사건·선택지는 선택적 `nextEventId`와 조건부 `branches: [{ conditions, nextEventId }]`를 지원한다. 선택지 직접 지정 → 사건 직접 지정 → 선택지 조건 분기 → 사건 조건 분기 → 일반 추첨 → 안전 사건 순서다. 분기는 선택 효과와 방금 완료한 선택 기록을 반영한 다음 단계 상태에서 판정한다. 목적지가 이미 방문했거나 대상·단계·조건을 만족하지 않으면 다음 순위로 넘어간다. 존재하지 않는 ID는 오류다.

Phase 2에서 기존 문서와 호환되는 선택 필드 세 개를 추가했다.

| 필드 | 의미 |
|---|---|
| `chaosWeight` | 0~5. 유효 가중치 = `weight × (1 + chaosWeight × chaos / 100)`. 생략하면 원래 가중치. 효과의 보상·손실은 증폭하지 않는다. |
| `isFallback` | 안전 사건 여부. 일반 추첨에서 제외하고 모든 일반 후보가 소진됐을 때 사용한다. 세계관별 정확히 하나가 필요하다. |
| `revealsFate` | 사건에 진입하면 출생 시 정해진 숨겨진 운명을 공개한다. 이후 저장·변신에도 공개 상태를 유지한다. |

안전 사건은 `stage: any`, 존재 필터·사건 조건·선택 조건·분기·변신·운명 공개가 없는 데이터여야 한다. 일반 사건 방문 상한은 1회, 안전 사건만 최대 12회다. 전체 선택은 언제나 12회로 제한한다. 콘텐츠가 충분한 정상 샘플 경로에서는 안전 사건을 사용하지 않는다.

엔딩에는 `priority`, `isDefault`, `worldIds`를 둔다. 사건 또는 엔딩을 등록하면 모든 세계관에 무조건 기본 엔딩 하나가 필요하다. 12번째 선택 효과를 반영한 뒤 조건을 만족하는 엔딩을 우선순위 내림차순·ID 오름차순으로 선택한다. 기본 엔딩의 우선순위는 다른 엔딩보다 낮게 작성한다. 현재 MVP는 일반 사건 185개·안전 사건 6개·엔딩 30개다. `src/content/mvp.ts`는 세계별 공통 12개 이상, 존재별 전용 3개 이상, 범용 18개 이상 등의 최소 수량과 도달성을 검사한다. 안전 사건은 일반 콘텐츠 수량에 포함하지 않는다.

## 시드, 상태, 공개 정보

시드는 0~4294967295 정수, 난수 알고리즘은 `mulberry32-v1`이다. 같은 콘텐츠 버전·시드·선택 기록은 같은 인생을 만든다. ID 정렬로 manifest와 옵션 배열 순서 변경의 영향을 없앤다. localStorage에 현재 난수 상태까지 저장한다. 선택지·조건 분기·효과 배열의 순서는 의미가 있으므로 변경 시 콘텐츠 버전도 갱신한다.

상태는 현재 존재와 출생 존재를 별도로 보관한다. 출생 선택 ID의 `null`은 생성 중 내부 상태를 위한 것이며, 정상 반환되는 출생에는 위치·특징·결함·숨겨진 운명 ID가 모두 채워진다. 저장 로더는 엄격한 스키마와 버전을 검사한 뒤 동일 시드·선택을 재실행하여 전체 상태를 비교한다. ID·조건·능력치·단계·난수·운명 공개가 기록과 다르면 복원을 거부한다. 엔진과 저장 규칙의 상세 설명은 `ENGINE.md`를 참고한다.

출생 이야기 치환자는 `{world}`, `{entity}`, `{location}`, `{trait}`, `{flaw}`만 허용한다. UI에 전달하는 `birthPreview()`는 숨겨진 운명의 ID·설명과 내부 플래그를 제외하고 `미공개`로 표시한다. 이는 게임상 비공개 처리이며 정적 웹게임의 소스 데이터를 암호화하는 기능은 아니다.
